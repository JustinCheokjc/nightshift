# Landing page hand-off for developers

The website now lives in `site/`. Deploy that folder as the site root on any static host (Netlify, Vercel, Cloudflare Pages, GitHub Pages). It has real pages: `/`, `/contributors/`, `/buyers/`, `/trust/`, `/about/`, `/join/` and `404.html`, sharing `assets/site.css` and `assets/site.js` (`assets/scene3d.js` is home only). Each page has its own title, description, canonical URL and Open Graph tags, and `sitemap.xml` lists them all. Old single-page links such as `/#join` or `/#faq` redirect to the new pages. `landing-page.html` in the project root is the old single-file version and is no longer the source.

To preview locally, links are root-relative, so run a server instead of opening the files: `cd site` then `python -m http.server`.

**Domain:** every absolute URL uses `https://nightshift.example`. Once the domain is chosen, find-and-replace it across `site/`.

Header and footer are repeated in each page's HTML. Change all six pages (plus `404.html`) when editing them.

## Replace before launch
- **Brand name:** change `BRAND` at the top of the script. Check domain, trademark and social handle availability first.
- **Contact email:** change `CONTACT` (currently hello@example.com) in the script and the About page.
- **Founder details:** add photo, bio and LinkedIn link on the About page.
- **Privacy notice and consent form:** replace the draft wording with text reviewed by a qualified adviser (PDPA). Fill the `[X]`, `[region]` and `[provider]` placeholders.

## Connect the sign-up form
- The prototype cannot send data to other sites. Set `FORM_URL` to a real endpoint (Tally, Airtable, Google Forms proxy or your own API) on the production host.
- Send an automatic confirmation email, and store the consent timestamp and policy version with each sign-up.

## Analytics
- The page already emits events via `track()` into `window.dataLayer` and an optional `window.NS_TRACK(event)` hook.
- Events: `page_view` (replaces the old `tab_view`), `cta_click`, `calc_used`, `eligibility_complete`, `scroll_depth`, `screen_view`, `form_submit`. `cta_click` and `scroll_depth` include the page.
- PostHog is connected with `persistence: 'sessionStorage'` (no cookies, cleared when the tab closes) and session recording disabled in code. The privacy notice on /about/ says this, so update it if either setting changes.
- `/join/?as=buyer` pre-selects the buyer option (used by the Buyers page button).

## Product film
- The 30-second film on the home page is `assets/nightshift-film.mp4` (1080p, about 2.6 MB), with `nightshift-film-720.mp4` for small screens and `film-poster.jpg` as its still. It plays muted while on screen (browsers block autoplay with sound), pauses when scrolled away, and never autoplays with reduced motion. A "Sound on" button unmutes it. A transcript sits under it.
- **Music:** an original track generated by `site/film/music.py` (standard-library Python, no samples), so there are no licensing issues. To regenerate: `python site/film/music.py music.wav`, then mix into each MP4 with `ffmpeg -i nightshift-film.mp4 -i music.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 160k -shortest -movflags +faststart out.mp4`. To use your own licensed track instead, run the same command with your audio file in place of `music.wav` (trim or fade it to 30 seconds).
- Its source is `site/film/index.html`, an animated page drawn frame by frame (open it to preview; it loops). To change the film, edit that page, then re-record: load `/film/?capture` at 1920x1080, call `window.film.seek(t)` for each frame (30 fps, 900 frames), screenshot each, and encode with `ffmpeg -framerate 30 -i f%04d.jpg -c:v libx264 -crf 20 -pix_fmt yuv420p -movflags +faststart nightshift-film.mp4`.
- If you change the film's wording, update the transcript on the home page too.
- Analytics: `film_play` (first play), `film_sound_on` and `film_complete`.

## Help chat
- `site/assets/chat.js` is a scripted FAQ bot (no AI, no server) on every page. Its answers live in the `KB` list at the top of the file: each has the question shown on its chip, trigger phrases (`keys`), the answer, an optional link and follow-up topics (`next`).
- When an FAQ or privacy answer changes on the site, update the matching `KB` entry too.
- Analytics events: `chat_open`, and `chat_question` with the answer id (or `none` when unmatched). What visitors type is never recorded, as the privacy notice promises. To see which questions go unanswered, ask visitors by email rather than logging their text.
- A/B test the headline with `?h=b`. Show a waitlist count only once it is real.

## Quality checks
- Test on real iPhone and Android devices. On screens 640px wide or narrower and with reduced motion, the "day" story uses a slider instead of the pinned scroll. With reduced motion, or if GSAP fails to load, the "How it works" steps show as a static row.
- Run a contrast and screen-reader pass (Lighthouse, axe, VoiceOver).
- Keep "planned" labels on anything not yet built. Do not publish earnings figures until the pilot produces measured data.
